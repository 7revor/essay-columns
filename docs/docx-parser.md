# DOCX 解析逻辑说明

## 概述

解析分三层，每层只做一件事：

```text
.docx ──► docxStructure.ts ──► segmentation.ts ──► essayRoles.ts ──► Essay[]
          读出带特征的文本块      切分作文边界         给每行标注角色
```

`parseDocx(file)` 走完整流程；`parseTextEssays(lines)` 把纯文本行（空行表示空段）包装成文本块后走同一流程，主要供测试使用。

## 数据结构

```ts
type LineRole = "meta" | "template" | "marker" | "title" | "body";

interface Essay {
  lines: { text: string; role: LineRole }[]; // 按原文顺序
  sourceHeader?: string;                     // 真实页眉
}
```

| 角色 | 含义 | 默认处理 |
| --- | --- | --- |
| `meta` | 姓名、班级、学校、指导老师等个人信息 | 移入页头（“提取个人信息”关闭时留在正文原位） |
| `template` | 各篇共有的模板行，如“作文批改报告”“【润色提升】”“（完）” | 默认删除，可在模式面板取消 |
| `marker` | 纯篇章编号，如“第1篇”“作文2” | 默认删除，可在模式面板取消 |
| `title` | 题目 | “首段识别为标题”开启时居中加粗；未识别到题目时退回首段 |
| `body` | 正文 | 保留；跨篇重复的正文段落只在面板中列出，默认不删 |

## 第一层：OOXML 文本块

`docxStructure.ts` 直接读取 `word/document.xml`、关系、页眉和 `styles.xml`，输出 `DocxBlock[]`。每块是一个段落中的一行，或一个多单元格表格行，并带有：

- `section`：所在分节；页眉按 Word 规则继承，支持首页页眉；
- `pageBreakBefore`：分页符 `w:br type="page"`、段落属性“段前分页”（含样式继承），或非连续分节的起点；
- `blankBefore`：前面紧邻的空段数量（只承载分节符的空段不计）；
- `headingLevel`：标题样式或大纲级别，0 为最高级；
- `centered`、`bold`、`fontSize`：用于辅助识别题目；
- `tableCells`：多单元格表格行的各单元格文本。

结构处理要点：

- 块级内容控件 `w:sdt`、`w:customXml` 会展开读取，不丢内容；
- 文本框 `mc:AlternateContent` 只读 `Choice`，避免和 `Fallback` 重复；
- 修订删除内容 `w:del`、域代码 `w:instrText` 不计入文本；
- 只有一个非空单元格的表格行（常见于作文纸模板）按普通段落展开，保持段落边界；嵌套表格只读一次；
- 段内软换行拆成多块，便于识别多行个人信息。

## 第二层：作文切分

`segmentation.ts` 按信号强弱依次尝试，第一个切出至少两篇的策略生效：

1. **个人信息行**：把连续的信息行合成信息组，含人员信息（姓名、学生、作者或无标签的“三年级3班 张三”）的组为身份组。以第一组首行的键为锚点键，例如“姓名”；同组中锚点之前的行，如上一篇的“指导老师”，留给上一篇。
   - 最后一组之后没有正文时，视为文末署名，每组结束即一篇结束；
   - 否则锚点向前扩展：优先吸附到 4 块以内的分页或分节；没有分页时，统计锚点前连续的题目或模板行数，取至少 80% 的篇以及第一篇都满足的数量，最多 3 行。
2. **篇章编号**：“第N篇”“作文N”构成的 1、2、3…递增链。“一、题目”式列表编号只在文档以编号开头时采用，避免把单篇作文的小标题当成分篇。
3. **重复抬头或结尾行**：在文档前 3 块内首次出现的重复短行作为每篇起点；最后一次出现在文末的重复短行作为每篇终点。如果某个重复行在多数出现处后面紧跟正文长段，说明它是几篇作文共用的题目（如多名学生都写《我最喜爱的积木》），不作为抬头。
4. **分页与分节**：每段至少两块，且页眉各不相同，或至少 80% 的段以题目式短行或信息行开头。连续分节只有在页眉变化时才算边界。
5. **最高级标题样式**：只取最高一级，单篇作文里的二级标题不会触发切分。
6. **居中短标题**：要求标题之后的段落不居中，且居中段落不超过四成，以排除诗歌。
7. **连续空段**：阈值取“切点数不超过块数三成”的最小空段数，所以段间空一行的排版习惯不会触发切分。

第一个起点之前如果只有一两行短标题（如“三年级优秀习作集”），视为封面丢弃；否则单独成篇。

## 第三层：行角色

`essayRoles.ts` 逐篇标注角色：

- **正文起点**：第一行既不是信息行、编号，也不是短标题式的行。正文起点之前为开头区域，最后一行正文之后为结尾区域。
- **meta**：开头区域或结尾区域里的信息行。表格信息栏规整为“姓名：张三  班级：三年级3班”。
- **template**：标题式短行，在至少 60% 的篇（至少两篇）的开头区域或最后两行中出现。如果它在多数篇里正好处于题目位（正文前最后一个非信息行），视为大家共用的题目，而不是模板。
- **title**：开头区域中第一个题目式短行（不超过 30 字，去掉末尾引号括号后不以句末标点结尾）。

个人信息行的识别（`textPatterns.ts`）支持：

- 键名中间有空格，如“姓 名：”“班　级：”；
- `【姓名】张三` 写法；
- 一行多个键，如“学生：张三  学校：实验小学”；
- 键前是无标签的班级或学校，如“二年级（14）班  姓名：张三”；
- 无标签的“三年级（3）班 张三”；
- 键后紧跟引号的单键行（如“老师：“同学们好！””）视为对话，不当作信息行。

## 下游处理

`patternDetection.ts`：

- 模板行逐条、篇章编号合并为一条，列为“结构”模式，默认删除；
- 跨篇重复的正文段落列为“内容”模式，默认保留；
- `filterEssay` 按角色组装页头、题目和正文，真实页眉与正文信息行相同时不会重复。

## 回归覆盖

`tests/layoutDetection.test.mjs` 以最终渲染结果（页头、题目、正文）断言，覆盖：

- 分页符、段前分页、换页分节与连续分节，以及每节独立页眉；
- 批改报告模板（含仅两篇的情况）、内容控件、文本框、单元格作文纸、嵌套表格、表格信息栏、标题样式；
- 个人信息的多种写法与位置：带空格的键名、分两行、仅作者、无冒号、学校、文末署名、封面加文末指导老师、题目在前；
- 编号分隔与连续空段；
- 反向用例：单篇作文的小标题和二级标题不拆分，对话行不当作信息行，重复正文不默认删除，相同题目不当作模板；
- “提取个人信息”和“首段识别为标题”两个设置项，以及模板行可在面板中取消删除。
