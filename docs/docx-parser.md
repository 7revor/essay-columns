# DOCX 解析逻辑说明

## 概述

`src/utils/docxParser.ts` 负责把上传的 `.docx` 文件解析成作文数组。解析遵循“结构优先、文本兜底”的原则：先读取 WordprocessingML 的分节和页眉关系；只有结构不足以判断作文边界，或结构读取失败时，才使用纯文本启发式规则。

## 数据结构

```ts
interface Essay {
  delimiter: string;       // 纯文本模式识别出的固定分隔行，可为空
  paragraphs: string[];    // 作文正文段落
  sourceHeader?: string;   // 从真实页眉或正文个人信息行中提取的页头
}
```

`parseDocx(file)` 返回 `Promise<Essay[]>`。`sourceHeader` 会由 `patternDetection.ts` 带入最终排版的页头，不再依赖正文里是否保留个人信息行。

## 解析流程

```text
.docx 文件
  │
  ├─ 读取 word/document.xml、document.xml.rels 和 header*.xml
  │    │
  │    ├─ 分节结构像作文集合 → 每节作为一篇，并关联该节页眉
  │    └─ 普通排版分节 → 不据此拆分
  │
  └─ Mammoth 提取纯文本
       │
       ├─ 多个“姓名/学生 + 班级/年级”信息行 → 按可变信息行拆分
       ├─ 存在重复短行 → 按固定分隔行拆分
       └─ 都不存在 → 按连续空行拆分
```

结构解析异常会输出警告并回退到纯文本解析，不会静默丢失错误。

## 分节和页眉识别

`src/utils/docxStructure.ts` 直接解析 DOCX 的 OOXML：

- 识别段落级和正文末尾的 `w:sectPr`，按 Word 的真实分节边界拆分正文；
- 通过 `word/_rels/document.xml.rels` 解析 `w:headerReference`，支持默认、首页和偶数页页眉；
- 处理 Word 的页眉继承：当前节没有新引用时继续使用前一节的有效引用；
- 保留页眉中的文本、制表符、换行，以及正文表格中的单元格文本；
- 只有满足作文特征时才采用分节结果，避免把普通文档的横竖版切换或页边距分节误判成多篇作文。

当前采用以下作文特征之一：

1. 至少一半分节存在非空页眉，并且页眉多数包含人员与班级信息，或至少三个页眉中有足够多的不同内容；
2. 至少一半分节以“姓名/学生 + 班级/年级”信息行开头；
3. 至少三个分节，且至少 60% 的分节拥有相同首段。

## 页眉移入正文后的识别

当真实页眉被移到正文后，每篇开头的姓名、学生、班级或年级内容通常不同，不能再依靠“完全相同的分隔行”。纯文本解析会优先查找同时包含人员标记和班级标记的边界行，例如：

```text
姓名：张三    班级：四年级4班
学生：李四    年级：五年级
```

检测到至少两个此类边界后，每个信息行开始一篇新作文；该行保存为 `sourceHeader`，而非混入正文。这样即使姓名和学号各不相同，也能稳定拆分。

## 固定重复行兜底

若没有可变信息边界，解析器继续寻找完全相同、重复至少三次、长度不超过 50 字符的短行，并结合出现次数和间隔均匀度评分：

```text
cv = 标准差 / 平均间隔
score = 出现次数 × 1 / (1 + cv)
```

得分最高的行作为 `delimiter`。如果仍找不到边界，则只在两个及以上连续空行处拆分。

## 下游处理

解析结果传入 `patternDetection.ts`：

- `sourceHeader` 优先作为最终页头；
- 正文开头残留的信息行会被提取并与页眉合并，相同内容不会重复；
- `delimiter` 仍作为可选的“分隔标记”展示；
- 跨作文重复段落仍可作为装饰性内容过滤。

## 回归覆盖

`tests/docxParser.test.mjs` 覆盖以下场景：

- 多分节 DOCX 的真实页眉与正文一一对应；
- 页眉移入正文后仍按可变个人信息行拆分；
- 缺少有效分节时的纯文本兜底；
- 普通排版分节不会被误拆成多篇作文；
- 真实页眉与正文信息相同时不会重复输出。
